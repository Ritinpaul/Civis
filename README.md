## 📌 Executive Summary

Every monsoon, India's Silicon Valley (**Bengaluru**) collapses under predictable yet unmanaged urban crises:
- **Bellandur Lake & Sluice Spillways** overflow, submerging the critical Outer Ring Road tech corridor.
- **Silk Board Arterial Junction** locks up in multi-agency paralysis, freezing ambulances and emergency convoys.
- **Hebbal Expressway Choke Points** suffer stormwater surges, cutting off access to the international airport.

While modern cities possess CCTV cameras, flood sensors, and dedicated agencies (**BBMP, BTP, KFES, BMTC**), each operates in an isolated data silo. When an unprecedented, compound catastrophe occurs, static emergency playbooks fail.

**CIVIS** introduces a radical conceptual leap: **Autonomous Civic Self-Adaptation**.
When the city's AI workforce encounters a crisis it has no playbook or tool to solve, CIVIS **diagnoses the missing capability**, **synthesizes a new specialist agent on the fly**, **tests it through a 7-battery evaluation suite (catching and self-repairing its own failures)**, **enforces constitutional safety gates under Protocol Zero**, **dispatches a multi-agency swarm**, and **permanently persists the capability into the city's operational registry**.

The city no longer relies on slow bureaucratic meetings during a crisis—its intelligence dynamically grows.

### **Act I — The City Knows (Baseline Trust)**
- **Scenario (`INC-001`)**: Heavy monsoon downpour triggers localized waterlogging in Chennai/Bengaluru Zone 4.
- **Action**: The pre-existing 4-agent municipal workforce (`WeatherAgent`, `TrafficAgent`, `InfrastructureAgent`, `EmergencyAgent`) dispatches standard diagnostic read tools.
- **Outcome**: Rainfall crests, sluice pumps activate, alternate diversions are established. The crisis is contained cleanly, proving the baseline system is stable and operational.

### **Act II — The City Doesn't Know (The Capability Gap)**
- **Scenario (`INC-002`)**: Sluice wall collapse causes unprecedented underwater embankment erosion. Ambulances carrying critical patients are halted before a submerged causeway with unknown roadbed depth.
- **Action**: The emergency agent queries the municipal capability registry for submerged depth passability calculation.
- **Outcome**: **Search returns `found: false`**. The agent declares `INSUFFICIENT_CAPABILITY`, halts execution, and triggers the CIVIS Adaptation Engine.

### **Act III — The City Adapts (Forge, Failure Catch & Self-Repair)**
- **Capability Synthesis**: The Gemini-powered Forge analyzes the incident telemetry, decomposes operational requirements, and generates the candidate specialist: `PassageAgent` equipped with `flood_passability.calc`.
- **Adversarial Evaluation**: The agent is submitted to a 7-battery evaluation suite (`T01`–`T07`).
- **Self-Repair Loop**: In test `T03`, the initial candidate code fails edge-case waterflow resistance limits. The Failure Diagnostic engine pinpoints the arithmetic flaw, streams a corrected prompt back to Gemini, and re-executes tests until **100% pass rate** is achieved.
- **GovernOS & Protocol Zero**: Before live deployment, the candidate is locked under **Protocol Zero**. An operator receives a 30-second human authorization countdown with constitutional safety bounds.

### **Act IV — The City Has Grown (Swarm Execution & Permanent Persistence)**
- **Swarm Dispatch**: The newly authorized `PassageAgent` joins the existing 4 agents to form a coordinated 5-agent crisis swarm.
- **Resolution**: High-clearance tactical routes are calculated, sluice gates are dynamically adjusted, and ambulances are routed to safety.
- **Permanent Evolution**: `flood_passability` is permanently stored in PostgreSQL and synced to the Municipal Capability Directory with cryptographic SHA-256 provenance hashes. Future floods are solved in seconds.

## ⚡ Key Architectural Features

### 1. 👁️ Multimodal Computer Vision Perception
- **Live CCTV Feeds**: Real-time simulated video streams across critical urban choke points (`ORR-CAM-018`, `SLK-JUNCTION-04`, `HBL-EXPY-07`).
- **Tri-Spectral Switching**:
  - **Optical RGB**: Standard color imaging with object bounding boxes.
  - **Thermal FLIR Night Vision**: Simulated thermography with Ironbow pseudo-coloring, hot-spot tracking, and spot water temperature crosshairs.
  - **Gemini AI Semantic Segmentation**: Real-time neural polygon hazard masks classifying roadbed, cresting water levels, and pedestrian risk zones.

### 2. 🛡️ GovernOS & Protocol Zero Constitutional Safety
- **Bound Authority Enforcement**: Agents can only execute tools explicitly permitted by their active municipal charter (`allowed_tools`).
- **Tamper-Resistant Denial**: Any attempt by an agent to access unassigned tools (e.g. traffic signal overwrites or citizen registries) immediately halts execution and fires an `UNAUTHORIZED_TOOL_DENIED` audit event.
- **Human-in-the-Loop Gateway**: Critical city overrides require human-in-the-loop authorization via an emergency 30s countdown modal.

### 3. 📄 Publication-Grade ICS Form 209 Incident Action Plan (PDF)
- **Official Compliance**: Implements the international Incident Command System (**ICS Form 209**) standard used by disaster response agencies worldwide.
- **3-Page A4 Executive SITREP**: Includes embedded vector emblems, verbatim 911 radio dispatch transcripts, multi-agency resource allocation tables, weather telemetry, and cryptographic verification hashes.

### 4. 🕸️ Reactive Agent-to-Agent (A2A) Workforce Mesh
- **Interactive Graph**: Built with `@xyflow/react` featuring tactical dot-grid matrices, active execution pulses, and node telemetry drawers.
- **Live State Inspection**: Inspect agent manifest parameters, input/output schemas, authorization levels, and execution memory traces.

### 5. 🔏 Cryptographic Provenance Ledger
- Every adaptation cycle, prompt repair, evaluation run, and authorization decision is hashed with SHA-256 and chained into an immutable municipal audit log.

## 🚀 Quick Start Guide

### Prerequisites
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) (recommended for simplest setup)
- [Node.js 18+](https://nodejs.org/) & [Python 3.11+](https://www.python.org/) (if running without Docker)
- A [Google Gemini API Key](https://aistudio.google.com/)

---

### Option A: Running with Docker Compose (Recommended)

1. **Clone the repository**:
   ```bash
   git clone https://github.com/Ritinpaul/Civis.git
   cd Civis
   ```

2. **Configure Environment**:
   ```bash
   cp .env.example .env
   ```
   Open `.env` and configure your API key:
   ```env
   GEMINI_API_KEY=your_google_gemini_api_key_here
   ```

3. **Launch all services**:
   ```bash
   docker compose up --build
   ```

4. **Access CIVIS**:
   - **Tactical Command Center**: [http://localhost:3000](http://localhost:3000)
   - **FastAPI Interactive Swagger Docs**: [http://localhost:8000/docs](http://localhost:8000/docs)
   - **Backend Health Check**: [http://localhost:8000/health](http://localhost:8000/health)

---

### Option B: Local Development Setup (Manual)

#### 1. Backend Service
```bash
cd apps/api

# Create & activate virtual environment
python -m venv venv
# Windows:
.\venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Start PostgreSQL database (or set DATABASE_URL=sqlite:///./civis.db)
# Seed the initial 4 agents and 4 capabilities
python scripts/seed.py

# Launch FastAPI development server
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

#### 2. Frontend Service
```bash
cd apps/web

# Install dependencies
npm install

# Start Next.js development server
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) to view the application.
